# Commits and PR

- Write commit messages and the PR title in Conventional Commits style, and
  follow any further conventions the repository uses.
- Open the PR against the repository's default development branch unless the
  task needs another base.

## PR description

1. One sentence on why the change exists.
2. How the change alters the functional requirements, and the side effects to
   expect.
3. Up to three bullets on what reviewers should watch for.
4. A compact outline of the structural changes: schemas, types, file tree,
   component or call flow. Show modified shapes in `diff` blocks.
